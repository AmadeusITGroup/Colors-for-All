Help

What is Colors-for-all?

Colors for All turns a palette into an interactive contrast matrix. Each cell shows a foreground/background combination and its accessibility result. Compare WCAG contrast ratios with APCA guidance for the selected font size and weight, then create, name, reorder, and refine colors in the visual editor or synchronized JSON. Palettes are saved locally in your browser.

Modes

Select a contrast model in the palette header:

  • WCAG reports AA and AAA results.
  • APCA reports signed Lc values and typography-aware usage guidance.

Your selected model is remembered locally.

Features

Palette actions

Each palette can be created, edited, duplicated, deleted, downloaded, or saved locally. There is no fixed limit on the number of colors.

More options > Download saves the palette as palette-name_YY-MM-DD.json.

Reading the matrix

The matrix places background colors in rows and text colors in columns. WCAG ratios or APCA Lc values are computed for every pair, and accessible results are highlighted. The count in the top-left cell follows the selected model and filters. Reversing foreground and background creates a separate combination.

Export accessible combinations

Choose More options > Export accessible colors to export only combinations that pass the selected model and the active filters. JSON, XLS, CSV, TXT, and PDF are available. XLS, PDF, and TXT headers identify the selected filters and show the palette, model, relevant APCA mode and typography, and result count together in one pipe-delimited row. PDF also includes previews of both colors.

Import a palette

Use Upload file in the homepage header to import a palette, then Click Save in the creation dialog.

Palette Editor

Color picker and JSON

The editor has two synchronized tabs. Valid JSON edits update the visual list, and visual edits update the JSON. Invalid drafts remain visible without replacing the last valid list; saving stays disabled until the draft is corrected.

Each color has a preview, editable value, drag handle, move controls, and a menu for duplication or deletion. Add color appends a new color.

Color names

Names are optional. Set a name in the Color picker, or use an object such as {"hex":"#0C66E1","name":"Primary-60"} alongside unnamed hex strings in JSON. Names follow colors when they are moved, duplicated, or deleted. Matrix headers show a name above its hex value; clearing a name restores hex-only display.

Color values and saving

Select a color preview to open the integrated picker in HEX format. RGB and HSL are available in the picker window. Palette colors are stored as opaque six-digit sRGB hex values; transparent colors are not supported. Cancel discards unsaved changes.

APCA rules

APCA reports signed lightness contrast (Lc), rounded to one decimal place. Positive values mean dark text on a light background; negative values mean light text on a dark background. Rows are backgrounds and columns are text colors. Reversing the colors can change both the sign and magnitude.

Checks and usage labels

A check marks combinations with an unrounded absolute Lc of at least 15, regardless of selected size or weight. A cross and faded sample mark combinations below that threshold. A check is not approval of text readability. The Lc value remains visible for the selected typography.

When a combination meets the contrast threshold, its usage label reflects both unrounded absolute Lc and the selected typography, not just the highest contrast band. Body, fluent, and large-text labels use the Bronze guidance below. When no text usage qualifies, the label is “No text”; the cell can still receive a check. Absolute Lc values from 15 to below 30 always show “No text”.

Spot-text eligibility uses fontLookupAPCA for a size/weight minimum not specified in the Bronze summary. This fallback never grants a body or fluent label. Tooltip minimums identify the lowest supported text usage, which may be spot text. Non-text-only and unsupported entries do not qualify as text.

Weights 800 and 900 use the 700-weight Bronze bracket. Sizes are CSS reference pixels based on Arial/Helvetica-like fonts with an x-height ratio around 0.52; other typefaces may need size or weight adjustments. These guidelines are not a guarantee for every typeface or for prolonged body-text reading.

APCA recommendations are not WCAG 2 AA/AAA conformance. APCA remains a developing method.

90Small body text only Preferred body-text level: at least 18px/300 or 14px/400. Extremely thin 200-weight text requires at least 24px. Non-body text can use 12px/400. Higher contrast has no ceiling for small text.
75Body text OK Body-text minimums: 24px/300, 18px/400, 16px/500, or 14px/700. Non-body text can use 15px/400. The Lc 60 size/weight combinations also qualify as body text after adding Lc 15.
60Fluent text only Readable content, not body columns or blocks: at least 48px/200, 36px/300, 24px/400, 21px/500, 18px/600, or 16px/700. Add Lc 15 to use these sizes for body text.
45Large & Sub-fluent text Headlines and large non-body text: at least 36px/400 or 24px/700. Also the minimum contrast for fine-detail pictograms and small outline icons.
30Spot & Non text only Minimum contrast for spot-readable text such as placeholders, disabled text, and copyright notices. Also for understandable solid semantic icons with a smallest solid dimension of at least 5.5px.
15No text Non-semantic non-text only, with a smallest solid dimension of at least 5px: for example, dividers or thick outlines, not fine details. This does not qualify any text combination as accessible. Treat lower contrast as invisible for many users.

Limits and non-text

Lc 90 is a suggested maximum for text larger than 36px at bold weight (700 or heavier), and for large areas of color. A tooltip warns when selected very large bold text exceeds that level; this advisory does not change Lc or automatically fail the combination. Small fonts have no maximum.

The matrix does not evaluate icon shape, stroke thickness, solid dimensions, or whether a non-text element is semantic. Its check or cross does not certify those non-text requirements.

Calculation and references

Calculations run locally using the unmodified apca-w3 0.1.9 library (algorithm 0.0.98G-4g), by Andrew Somers / Myndex. References: APCA Contrast Calculator, Why APCA, font lookup tables, and questions and issues.

This integration is intended for evaluating web content on self-illuminated displays and is subject to the APCA-W3 license and notices.
